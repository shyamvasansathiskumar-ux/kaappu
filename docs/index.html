    01 · The problem

    Nobody hacks your 2FA. You drop it.

    The usual way people lose their two-factor accounts isn't an attacker. It's a dropped phone, a factory reset, or an app that never synced. Recovery codes get printed once and filed somewhere nobody remembers.

    i.

    The phone breaks

    Every secret lived in one app, on one device.

    ii.

    The backup is a password

    Forget it, or lose the person who knew it, and the backup is a locked box.

    iii.

    Kaappu splits the key

    Three shares in three places. Any two open the vault. One alone is useless to a thief.

    04 · Shamir's Secret Sharing

    Any two rebuild it. One alone reveals nothing.

    Each byte of the key becomes the starting point of a random curve. Every share is one point on every curve. Two points fix a line, so any two shares give the key back. One point fits every possible key equally well, so one share says nothing.

    The arithmetic happens in GF(2⁸), the same 256-element field AES uses, so nothing ever overflows and nothing leaks through rounding. Each share ends in a checksum, so a one-character typo is caught before it can rebuild the wrong key.

      05 · The vault

      Locked like it matters.

      AES-256-GCM

      The vault file is encrypted and authenticated. Flip one bit and it refuses to open.

      PBKDF2 · 600,000

      Your password is stretched with HMAC-SHA256, 600,000 rounds, before it becomes a key.

      Two keys

      Shares are taken of the data key, not your password, so they still work after you change it.

      Atomic writes

      The file is written to a temp file and moved into place, chmod 600. A crash never leaves half a vault.

      No argv secrets

      Secrets are read from a hidden prompt, never the command line, so they stay out of shell history and ps.

      QR tamper check

      If the issuer in a QR link's label disagrees with its issuer field, Kaappu refuses it instead of guessing.

      07 · Run it

      Plain Java. Read it in an evening.

      It started as a project my dad set me: build an authenticator from the RFCs, without a library doing the interesting part. Needs JDK 17 or newer.

      Read this before trusting it

      A learning project that takes security seriously, not an audited product. SECURITY.md lists what it defends against and where it stops. For your bank, keep your phone's authenticator too, and treat Kaappu as the backup you can actually recover.

      $ sh build.sh test        # 70 checks, every RFC vector
$ sh build.sh
$ java -jar build/kaappu.jar init
$ java -jar build/kaappu.jar add
$ java -jar build/kaappu.jar backup 2 3
Any 2 of these 3 shares can open this vault without the password.
Store each one in a different place. Fewer than 2 reveal nothing.
